缺 sitemap，丢的是「收录入口」

站点地图是给爬虫看的清单：URL 有哪些、最后更新时间是什么。没有它，爬虫发现新文章的路径只剩下两条——从首页链接往外爬，或者从别人给的外链进来。

对于一个每天更新一篇的博客，这件事值得较真：第 6 篇、第 7 篇如果没被任何地方链接过，它凭什么被找到。GitHub Pages 是纯静态托管，不会替你生成 sitemap，这件事必须由构建流程来做。

robots.txt 缺的不是「允许」，是「声明」

robots.txt 不存在的时候，语义上等于允许一切抓取——所以缺它不算封站。

丢的是另一件事：这是唯一一个免费、且被主流爬虫默认读取的位置，可以在里面写一行 Sitemap:，把站点地图的地址主动告诉对方。不写，爬虫也能自己找到（如果站点地图叫标准名字、放在根目录），但这属于「被默认发现」，不是「你声明了」。

这个是我在产物里 grep 才发现的。打开任意一篇文章的 HTML 头部：

而我实际分享出去的地址是 https://tedoverlearn.github.io/2026/10/29/public-info-ai-aggregation/，没有 index.html 尾巴。两个地址在 GitHub Pages 上都能打开，canonical 却指向带尾巴的那个。

原因在 Hexo 的 pretty_urls.trailing_index，默认值是 true。官方配置文档里给的正是一个对照例子：

顺带一句文档里的提醒：trailing_html 对尾部的 index.html 无效，要去掉它只能靠 trailing_index。

这不是灾难，但它是「同一篇文章存在两个可访问 URL」的典型形态。要不要改，取决于你更在意产物的干净，还是在意已经存在的链接——改配置会让全站所有 URL 的形态一次性变化，这是一次有影响面的改动，不能当成随手一行。

一处已经付过学费的配置

比起上面三处，url 才是真正昂贵的那一个。

我建站时的 _config.yml 里写着 url: http://example.com——脚手架默认值，一直没动。它不影响页面渲染，所以看不出来。但所有绝对地址都从它派生：canonical、og:url、站点地图、RSS 里的链接，全是 example.com。

也就是说，那段时间每个页面的头部都在告诉搜索引擎：这篇文章的正式地址在别人家的域名上。

改成一个字符串就能修好，但它是那种「改一个字，45 个 HTML 文件的头部同时变」的配置——越是不影响浏览体验的配置，越容易被忘掉。

三处怎么补（我还没动）

  1. 装 sitemap 生成器，按上面的 sitemap.path 配置，重新 hexo generate，确认 public/sitemap.xml 真的出现了——不看产物就当它成功了，是上一次踩过的坑。
  2. 在 source/ 下放一个 robots.txt，写上 Sitemap: 那一行。它是纯文本，Hexo 会原样复制进 public/。
  3. pretty_urls.trailing_index: false——这一项我先不改。它影响全站 URL 形态，改完要重新生成、逐页检查 canonical，还要想清楚旧链接怎么办。想做的时候单独做，不和别的事情混在同一个提交里。

为什么值得记下来

站点问题大多长一个样：配置的默认值 + 从没看过产物。默认值不会报错，产物不会喊疼，等发现的时候往往已经积累了几个月。

一次巡检只有三条命令。比读一小时文档有用，也比在搜索框里输入「Hexo 为什么不被收录」有用——那个问题的答案，很多时候就写在你自己 public/ 目录的文件列表里。
